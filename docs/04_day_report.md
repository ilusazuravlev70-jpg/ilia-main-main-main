# Итоговый отчет: День 4. Создание схемы базы данных

## Что сделано

1.  Создан файл базы данных `db/shoe_store.sqlite` с помощью скрипта `src/db_init.py`.
2.  Реализованы DDL-скрипты для всех семи таблиц: `roles`, `sizes`, `users`, `products`, `stock_items`, `orders`, `order_items`.
3.  Добавлены первичные ключи (`PRIMARY KEY AUTOINCREMENT`) и внешние ключи (`FOREIGN KEY`).
4.  Настроены ограничения целостности:
    *   `NOT NULL` для обязательных полей (фамилия, название товара).
    *   `UNIQUE` для логина и названия роли.
    *   `CHECK` для проверки диапазонов (цена > 0, размер обуви от 20 до 50).
    *   `DEFAULT 0` для количества товара на складе.
5.  Включена принудительная проверка внешних ключей через `PRAGMA foreign_keys = ON`.
6.  Созданы индексы на внешние ключи (`role_id`, `user_id`, `product_id`) и часто фильтруемые поля (`category`, `order_date`) для ускорения `JOIN` и поиска.
7.  Структура базы проверена визуально через SQLite Viewer и программно через скрипт `db_structure_check.py`.
8.  Проверена работа ограничений на практике через скрипт `db_test_constraints.py`. Все тесты пройдены успешно.
9.  Структура базы экспортирована в файл `db/schema.sql` (через SQLite Viewer).
10. База заполнена тестовыми данными через скрипт `db_seed.py`.
11. Написаны проверочные SQL-запросы в `queries/04_check_queries.sql`.

## Принятые решения

*   **Порядок создания таблиц:** Таблицы создавались от справочников (`roles`, `sizes`) к транзакционным (`orders`, `order_items`), чтобы внешние ключи всегда ссылались на уже существующие таблицы.
*   **Стратегии удаления:** Для `orders.user_id` выбран `RESTRICT` (нельзя удалить клиента, если у него есть история заказов). Для `order_items.order_id` выбран `CASCADE` (при удалении заказа его позиции удаляются автоматически, так как без заказа они не имеют смысла).
*   **Тип данных для размера:** Используется `REAL`, так как размер обуви может быть дробным (например, 36.5).
*   **Тип данных для даты:** Используется `TEXT` в формате ISO 8601 (`YYYY-MM-DD`). В SQLite нет нативного типа `DATE`, а хранение даты как строки позволяет легко сортировать и сравнивать их стандартными строковыми операциями.
*   **Индексы:** Индексы созданы только на поля, участвующие в связях (`*_id`) и поиске (`category`, `order_date`), чтобы не замедлять вставку данных избыточной индексацией.
