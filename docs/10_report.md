# Отчет: День 10. Хранимые процедуры и функции

## 1. Теоретическая часть
**Разница между функцией и процедурой:**
*   **Функция** — возвращает значение (как калькулятор). Вызывается внутри `SELECT`. Не должна менять данные.
*   **Процедура** — выполняет действие (меняет данные: `INSERT`, `UPDATE`). Вызывается командой `CALL`. В SQLite процедур нет, они эмулируются через Python с использованием транзакций (`commit`/`rollback`).

## 2. Реализация на Python (SQLite)
В файле `src/procedures_functions.py` реализованы:
*   **Функции:** `calc_order_total` (умножение с проверкой на None), `get_category_count` (принимает `conn` и делает запрос), `format_phone` (приведение к формату +7...), `create_order` (транзакция создания заказа), `update_stock` (списание с проверкой на минус).
*   **Транзакции:** В `create_order` используется `conn.commit()` при успехе и `conn.rollback()` при любой ошибке (например, если товара не хватило). Это гарантирует, что заказ не создастся "наполовину".

## 3. Результаты SQL-запросов (с использованием функций)
*(Здесь нужно вставить результаты выполнения запросов из Блока 1, например:)*
1.  **Сумма заказа:** `SELECT order_id, CALC_ORDER_TOTAL(price, quantity) FROM order_items;`
2.  **Формат телефона:** `SELECT FORMAT_PHONE('89991234567') FROM users;`
3.  **Количество в категории:** `SELECT category, count_in_category('Кроссовки') FROM products GROUP BY category;` (требует регистрации функции в Python-скрипте).

## 4. Код для PostgreSQL
В файле `db/procedures_functions.sql` представлен синтаксис `CREATE FUNCTION` и `CREATE PROCEDURE` на языке `plpgsql`. Реализована обработка исключений через блок `EXCEPTION` и вывод сообщений через `RAISE NOTICE`.

## 5. Итог
Все Python-функции протестированы на граничные случаи (None, отрицательные числа). Транзакции работают корректно: при ошибке списания остатков заказ не создается.
